# «Автонова с пробегом» — сайт дилерской площадки (Гомель, ул. Мазурова, 112)

Готовый к развёртыванию сайт: каталог автомобилей с пробегом, карточки с фотогалереей, сравнение и
избранное, услуги (кредит, лизинг, обмен, выкуп, комиссия), автожурнал, калькулятор, отзывы,
проданные автомобили, приём заявок и личный кабинет продавца с админ-панелью.

Технологии: **Node.js без единой внешней зависимости** (только стандартная библиотека), серверный
рендеринг на `node:http`, база — встроенный `node:sqlite`. Сборка не требуется: `node_modules`
отсутствует как понятие, `npm install` не нужен.

---

## 1. Требования

| Что | Значение |
|---|---|
| Node.js | **24.0 или новее** (нужен встроенный модуль `node:sqlite`; проверено на 26.8) |
| Свободный порт | по умолчанию `8100` |
| Диск | ~60 МБ (фотографии каталога) + база данных |
| Права | запись в `data/` (база) и `public/uploads/user/` (фото из админки) |

Внешних сервисов и интернета на хостинге не требуется: шрифты, стили, скрипты и картинки
раздаются самим сайтом.

## 2. Быстрый старт

Linux/macOS:

```sh
cd autonova-2
PORT=8100 PUBLIC_BASE=https://autonova.by ADMIN_PASSWORD='свой-пароль' ./start.sh
```

Windows (двойной клик или из консоли):

```bat
start.cmd
```

Или напрямую:

```sh
node server.mjs            # http://127.0.0.1:8100
```

При первом запуске сервер сам создаёт `data/autonova.db`, наполняет каталог из
`data/seed-cars.json`, добавляет услуги, статьи, отзывы и создаёт администратора.

## 3. Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT` | `8100` | порт сервера |
| `HOST` | `127.0.0.1` | интерфейс прослушивания. За обратным прокси оставьте по умолчанию; для прямого доступа извне — `0.0.0.0` |
| `PUBLIC_BASE` | `http://127.0.0.1:8100` | **канонический адрес сайта** для `canonical`, `og:url`, микроразметки, `robots.txt` и `sitemap.xml`. На боевом домене задайте `https://autonova.by` |
| `ADMIN_PASSWORD` | `autonova2026` | пароль создаваемого администратора (`admin@autonova.by`). Читается **только при первом запуске**, когда пользователей ещё нет — задайте свой пароль заранее |
| `AUTONOVA_DB` | `data/autonova.db` | путь к файлу базы (например, для выноса данных на отдельный диск) |

> Пароль администратора, созданный при первом запуске, в дальнейшем меняется в разделе
> «Настройки» админ-панели либо сбросом записи `admin@autonova.by` в таблице `users`.

## 4. Запуск как служба

`/etc/systemd/system/autonova.service`:

```ini
[Unit]
Description=Autonova s probegom
After=network.target

[Service]
Type=simple
User=www-data
WorkingDirectory=/var/www/autonova-2
Environment=NODE_ENV=production
Environment=PORT=8100
Environment=HOST=127.0.0.1
Environment=PUBLIC_BASE=https://autonova.by
ExecStart=/usr/bin/node server.mjs
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```

```sh
sudo systemctl daemon-reload && sudo systemctl enable --now autonova
```

Проверка без systemd — `pm2 start server.mjs --name autonova`.

Обратный прокси (nginx) — единственное место, где указывается домен и сертификат:

```nginx
server {
  listen 80;
  server_name autonova.by www.autonova.by;

  location / {
    proxy_pass http://127.0.0.1:8100;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-Proto $scheme;
  }

  # статика с фото кэшируется браузером, версии в ссылках уже проставлены
  location /assets/ { proxy_pass http://127.0.0.1:8100; proxy_cache_valid 200 7d; }
}
```

HTTPS удобнее получить через `certbot --nginx`.

## 5. Проверка после развёртывания

```sh
node tests/regression.mjs --base=https://autonova.by     # полный набор проверок сайта
node tests/regression.mjs --list                         # список разделов проверок
node tools/clean-demo-data.mjs                           # убрать тестовые аккаунты после проверок
```

Проверки работают через HTTP и не требуют браузера. Тестовые регистрации создают аккаунты вида
`*@example.com` — их удаляет `tools/clean-demo-data.mjs` (администратор не затрагивается).

## 6. Состав поставки

```
server.mjs                точка входа: маршруты, статика, обработка форм
lib/                      логика: база, авторизация, выборки, страницы, макет
  db.mjs                  подключение SQLite и схема таблиц
  seed.mjs                первичное наполнение каталога и контента
  auth.mjs                регистрация, вход, сессии (scrypt-хеши паролей)
  cars.mjs                фильтры, сортировки, карточки
  pages.mjs               страницы сайта и админ-панель
  view.mjs                общий макет, шапка, подвал, компоненты
public/                   всё, что отдаётся как есть
  assets/css|js|logo/     стили, скрипты, логотипы, favicon
  uploads/seed/           фотографии автомобилей каталога
  uploads/user/           фото, загруженные через админку (каталог создаётся при загрузке)
data/seed-cars.json       источник каталога: 57 автомобилей, 120 фотографий
tests/regression.mjs      набор проверок сайта
tools/clean-demo-data.mjs чистка тестовых аккаунтов
start.cmd / start.sh      запуск на Windows / Linux
```

Файл базы `data/autonova.db` в поставку **не входит** и создаётся при первом запуске — вместе с
ним появляются `-wal` и `-shm` (режим WAL). Резервная копия делается копированием всех трёх файлов
либо командой `sqlite3 data/autonova.db ".backup backup.db"`.

## 7. Обновление и наполнение

- **Каталог** правится в админ-панели (`/admin`) либо заменой `data/seed-cars.json` с последующим
  добавлением записей; удаление автомобиля из каталога — в разделе «Автомобили».
- **Заявки** посетителей попадают в раздел «Заявки», отзывы — в «Отзывы», настройки телефонов и
  адреса — в «Настройки».
- **Фотографии**, загруженные через админку, лежат в `public/uploads/user/<slug>/` — этот каталог
  должен быть доступен на запись и попадать в резервные копии.
- После правки `public/assets/css/site.css` или `site.js` увеличьте номер версии в ссылке
  (`?v=100`) в `lib/view.mjs` — тогда у посетителей не останется старой копии из кэша.

## 8. Частые вопросы

**Нужен ли `npm install`?** Нет, зависимостей нет.

**Почему без `PUBLIC_BASE` в ссылках виден `127.0.0.1`?** Это значение по умолчанию для локального
запуска; на боевом домене обязательно задайте `PUBLIC_BASE=https://ваш-домен`.

**Где `robots.txt` и `sitemap.xml`?** Отдаются сервером автоматически из текущего содержимого
каталога и статей; адрес подставляется из `PUBLIC_BASE`.

**Как сменить порт?** `PORT=8200 node server.mjs` либо правка `start.cmd` / `start.sh`.

## 9. Публикация в интернете за несколько минут (Render, бесплатно)

В поставке лежит `render.yaml` — описание службы для [Render](https://render.com/): банковская карта
не нужна, HTTPS и публичный адрес выдаются сразу, сайт слушает `0.0.0.0` и порт из переменной `PORT`.

1. Откройте [dashboard.render.com/blueprint/new](https://dashboard.render.com/blueprint/new?repo=https://github.com/akkountmy/autonovaBY)
   и войдите через GitHub (одна авторизация; Render читает репозиторий, ничего в нём не меняет).
2. Render найдёт `render.yaml` в репозитории `akkountmy/autonovaBY` и предложит создать службу
   `autonova`. В поле `ADMIN_PASSWORD` впишите **свой** пароль администратора: значение по умолчанию
   `autonova2026` опубликовано в этом файле и для боевого сайта не годится.
3. Нажмите «Create New Resources» / «Apply» и дождитесь конца сборки (1–3 минуты).
4. Публичный адрес появится в шапке службы: `https://<имя>.onrender.com`. Проверка —
   `node tests/regression.mjs --base=https://<имя>.onrender.com`.

Канонический адрес сайта подставляется автоматически из `RENDER_EXTERNAL_URL`, поэтому
`PUBLIC_BASE` задавать не нужно (он нужен только на своём домене, см. раздел 3).

Что важно знать про бесплатный тариф: служба засыпает после 15 минут без запросов (первый запрос
после паузы поднимает её примерно за минуту), а файловая система не сохраняется между запусками —
база создаётся заново при каждом старте, поэтому демонстрационные заявки и регистрации живут до
перезапуска. Для постоянного хранения данных нужен тариф с диском: подключите диск с точкой
монтирования `/var/data` и задайте `AUTONOVA_DB=/var/data/autonova.db`.

Тот же запуск руками на любом сервере с Node.js 24:

```sh
HOST=0.0.0.0 PORT=10000 ADMIN_PASSWORD='свой-пароль' node server.mjs
```
